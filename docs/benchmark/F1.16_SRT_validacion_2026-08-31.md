## 5. Ajustes realizados durante F1.16

### 5.1 Restricción de lectura

La primera variante utilizaba una denegación amplia sobre `/home` con excepciones `allowRead`.

En Linux/bubblewrap esta estrategia produjo interferencias con rutas necesarias para SRT y con la semántica de montajes anidados.

Se reemplazó por una política de lectura sensible explícita, manteniendo la escritura como allowlist.

### 5.2 Ruta AWS en WSL

`/home/cumplebench/.aws` resultó ser un enlace simbólico:

`/home/cumplebench/.aws -> /mnt/c/Users/aleja/.aws`

La aplicación directa de `denyRead` sobre el symlink provocó un error de montaje de bubblewrap.

La política se corrigió protegiendo el destino real:

`/mnt/c/Users/aleja/.aws`

### 5.3 Claude Code

Claude Code se instaló mediante el instalador nativo.

Se verificó su ejecución dentro de SRT como:

`2.1.252 (Claude Code)`

La configuración del benchmark se aisló de `~/.claude` utilizando `CLAUDE_CONFIG_DIR`.

## 7. Evidencia de aislamiento de red

Con allowlist vacía, una solicitud a Internet fue interceptada por SRT con:

`X-Proxy-Error: blocked-by-allowlist`

Posteriormente se habilitaron únicamente:

- `api.anthropic.com`
- `platform.claude.com`

Ambos dominios resultaron accesibles, mientras que `example.com` continuó bloqueado por la allowlist.

Esto confirma que la política mantiene egreso selectivo y no acceso general a Internet.

## 8. Evidencia de localhost

Se levantó fuera de SRT un servidor HTTP temporal en:

`127.0.0.1:8765`

Resultado:

- fuera de SRT: ACCESIBLE;
- dentro de SRT: BLOQUEADO.

El servidor temporal fue detenido al finalizar la prueba.
