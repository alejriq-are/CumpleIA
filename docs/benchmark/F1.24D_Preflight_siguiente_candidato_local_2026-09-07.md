# F1.24D — Preflight del siguiente candidato local

**Estado:** artefacto descargado y verificado; gates de runtime pendientes.

F1.24C descartó a Qwen3.5-9B como selección final por su resultado funcional
1/4. Este documento prepara la siguiente evaluación sin descargar un modelo,
modificar transporte ni ejecutar una corrida autoritativa.

## Decisión de viabilidad

Se evaluó Qwen3-Coder-Next como siguiente candidato. No es viable con el
equipo informado (RTX 5060 de 8 GB VRAM y 32 GB RAM): el GGUF Q4_K_M oficial
ocupa 48,4 GB sólo en pesos, por encima de la RAM disponible antes de KV cache,
runtime y sistema operativo. Sus 3B parámetros activos no reducen la memoria
necesaria para cargar sus 80B parámetros totales.

El candidato propuesto para preflight es **Qwen3-Coder-30B-A3B-Instruct,
Q4_K_M**. Los pesos base son [oficiales de Qwen](https://huggingface.co/Qwen/Qwen3-Coder-30B-A3B-Instruct);
el GGUF estático elegido se obtendrá de
[`mradermacher/Qwen3-Coder-30B-A3B-Instruct-GGUF`](https://huggingface.co/mradermacher/Qwen3-Coder-30B-A3B-Instruct-GGUF).
El archivo Q4_K_M publicado por ese conversor pesa 18.56 GB (17.28 GiB).
Por tamaño, puede caber en RAM con offload parcial a la GPU de 8 GB, pero esa
posibilidad no equivale a un PASS: deben medirse carga, memoria, contexto útil
y rendimiento en el equipo real.

La descarga del artefacto identificado por el preflight confirmó:

| Campo | Valor |
|---|---|
| Archivo | `Qwen3-Coder-30B-A3B-Instruct.Q4_K_M.gguf` |
| Tamaño anunciado | 18,6 GB |
| SHA256 | `050b8e7977edd2644093b691c899beb156deffdfe20cc33df7fa9ece3aaba257` |
| Espacio libre en volumen de modelos | 465 GB |

La revisión exacta del repositorio debe registrarse al obtenerla desde el Hub
o desde el metadata local de la descarga. Qwen3-Coder-Next continúa descartado
por su tamaño: su [GGUF Q4_K_M oficial](https://huggingface.co/Qwen/Qwen3-Coder-Next-GGUF)
ocupa 48,4 GB.

## Condiciones invariantes

La evaluación conserva:

- baseline `c29ac90b7486a8ab02af282b6c0978eaccd5809c`;
- tarea de selector activo y perfil `rat-active-organization-selector-v2`;
- verifier trusted existente;
- aislamiento SRT, managed settings y el endpoint local ya validado;
- configuración de Claude Code que funcionó en F1.24B: `chatml`,
  `--reasoning off`, `--reasoning-budget 0` y
  `--chat-template-kwargs '{"enable_thinking":false}'`.

No se reutiliza un resultado de Qwen3.5-9B. El nuevo candidato recibirá un
`candidateName` y `runId` nuevos después del preflight.

## Secuencia de preflight

1. Descargar una única cuantización Q4_K_M desde la revisión elegida, calcular
   SHA256 y registrar repositorio, revisión, nombre y tamaño del archivo.
2. Confirmar que el commit de llama.cpp soporta la arquitectura y, si debe
   actualizarse, fijar el nuevo commit antes de ejecutar pruebas. No mezclar
   esa actualización con la medición de F1.24C.
3. Arrancar el servidor OpenAI-compatible en el endpoint local ya autorizado,
   inicialmente con contexto de 8K y offload máximo que no produzca error.
   Registrar capas offloaded, uso de VRAM, RAM y parámetros de servidor.
4. Ejecutar smoke sin SRT y luego dentro de SRT con Claude Code. Debe responder
   mediante `chatml`, sin razonamiento, y resolver el nombre
   `llm-local.cumpleia` por la entrada existente de `/etc/hosts`.
5. Repetir el gate de contexto en 8K, 16K, 24K y 32K, con una prueba de
   prefill limpio de 24K. Registrar tokens procesados, duración, tok/s,
   tamaño KV y toda degradación o error. Un resultado que no llega a 32K se
   registra como tal; no se extrapola desde Qwen3.5-9B.
6. Si los gates operativo y de transporte pasan, crear artefactos nuevos de
   transporte y run en `docs/benchmark/runner/rounds/rat-active-organization-selector-v2/`.
   Deben satisfacer los esquemas y usar timeout común de 1.800 s, igual que
   F1.23C. Ejecutar el runner una vez y validar su evidencia con
   `verify_evidence.py`; conservar cualquier error de harness separado del
   resultado del modelo.

## Gate operativo 8K — PASS fuera de SRT

Se cargó el candidato con llama.cpp `b95502b` en el binding dedicado
`127.77.18.1:18080`, con `-c 8192`, `-ngl 99`, `-np 1`, template `chatml` y
razonamiento desactivado. El servidor informó `model loaded` y quedó escuchando
en el endpoint esperado.

Una llamada OpenAI-compatible solicitó responder exactamente
`F1.24D-8K-LOCAL-OK` y devolvió ese marcador con `finish_reason: stop`.

| Métrica | Resultado |
|---|---:|
| Contexto por slot | 8192 tokens |
| Prompt | 24 tokens / 1281.512 ms / 18.728 tok/s |
| Generación | 14 tokens / 3301.117 ms / 3.938 tok/s |
| VRAM posterior al smoke | 7766 MiB usados / 134 MiB libres |
| Memoria visible en WSL durante la carga | 15 GiB totales / 13 GiB disponibles |

El proceso usa memoria mapeada, por lo que su RSS informado no representa por
sí solo los pesos residentes en la caché del sistema. El siguiente gate es
Claude Code dentro de SRT; aún no se ha medido contexto 16K, 24K o 32K ni se
ha ejecutado una corrida funcional.

## Primer intento de smoke SRT — HARNESS_ERROR de preflight

Un smoke manual intentó usar un directorio temporal fuera de los paths de
escritura generados por el harness. SRT respondió:

```text
EROFS: read-only file system, mkdir '/home/cumplebench/runtime/f124d-srt-8k/tmp/claude-1000'
```

El agente no alcanzó al backend y no hubo inferencia del candidato; se clasifica
como error de infraestructura de preflight, no como resultado del modelo. El
siguiente intento debe generar una política SRT por runId con
`prepare_workspace.py`, que autoriza exclusivamente su TMPDIR corto y su
configuración efímera de Claude Code.

## Gate de transporte 8K — PASS dentro de SRT

Con un workspace, runtime, TMPDIR corto y política SRT generados por
`prepare_workspace.py`, Claude Code se ejecutó contra
`http://llm-local.cumpleia:18080` y devolvió exactamente:

```text
F1.24D-8K-SRT-OK
```

Persistió la advertencia no fatal
`[claude-code:unrecognized_model] {"model":"local", ...}`. Es la limitación
ya conocida del identificador lógico local; no impidió la inferencia. Este gate
confirma Qwen3-Coder-30B a 8K fuera y dentro de SRT. La prueba no fue una
corrida RAT y no modifica las evidencias históricas.

## Gate de transporte 16K — PASS dentro de SRT

Claude Code, usando el mismo endpoint aislado y la política SRT generada por
el harness, respondió exactamente:

```text
F1.24D-16K-SRT-OK
```

La advertencia `unrecognized_model` para `local` persistió sin afectar la
respuesta. Con ello, los gates operativo y de transporte están aprobados a 8K
y 16K. El siguiente gate es cargar 24K y medir un prefill limpio; no se ha
ejecutado todavía el benchmark funcional.

## Criterio de avance

Sólo avanza a la medición funcional si no hay OOM, el servidor responde a
Claude Code dentro de SRT y el contexto requerido resulta operativo. La
selección final exige un resultado funcional verificable superior al 1/4 de
Qwen3-4B y Qwen3.5-9B sobre este mismo contrato; no se anticipa el resultado.
