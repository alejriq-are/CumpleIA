# F1.24H — Preflight Qwen3.6-35B-A3B

Fecha: 2026-09-08

## 1. Objetivo

Evaluar Qwen3.6-35B-A3B como posible candidato local para CumpleIA,
aplicando un preflight progresivo antes de ejecutar una ronda funcional RAT.

Los gates definidos fueron:

1. compatibilidad del runtime llama.cpp;
2. integridad del artefacto GGUF;
3. carga CUDA y offload;
4. inferencia local a 8K;
5. conectividad mediante SRT;
6. compatibilidad con Claude Code;
7. ampliación posterior de contexto;
8. benchmark funcional RAT solamente si los gates anteriores resultaban PASS.

## 7. Transporte SRT

El transporte local canónico utiliza:

`http://llm-local.cumpleia:18080`

con resolución exclusiva:

`llm-local.cumpleia -> 127.77.18.1`

Durante el preflight se detectó que la entrada correspondiente de
`/etc/hosts` no estaba presente, provocando respuestas:

`HTTP/1.1 502 Bad Gateway`

Este incidente correspondió a configuración del entorno y no al modelo.

Se restauró:

`127.77.18.1 llm-local.cumpleia`

Posteriormente:

`GET /health`

ejecutado dentro de SRT devolvió:

`HTTP/1.1 200 OK`

Resultado transporte SRT:

**PASS**

## 8. Claude Code con template nativo

Se reprodujo el entorno utilizado por el trusted runner, incluyendo:

- HOME aislado;
- CLAUDE_CONFIG_DIR aislado;
- TMPDIR del benchmark;
- ANTHROPIC_BASE_URL local;
- ANTHROPIC_AUTH_TOKEN local sin secreto;
- modelId `local`;
- SRT con política generada por el harness.

Claude Code alcanzó correctamente el backend local.

Sin embargo, durante una operación interna:

`generate_session_title`

llama-server devolvió:

`HTTP 500`

con:

`Jinja Exception: System message must be at the beginning`

Esto demuestra que:

- Claude Code alcanza SRT;
- SRT alcanza llama-server;
- llama-server recibe la solicitud;
- la incompatibilidad ocurre en la aplicación del chat template nativo
  de Qwen3.6 frente a la secuencia de mensajes generada por Claude Code.

Resultado:

**FAIL**

## 9. Mitigación mediante chatml

Se realizó una mitigación controlada reemplazando el template nativo por:

`--chat-template chatml`

manteniendo el resto de la configuración.

El servidor cargó correctamente.

Sin embargo, el modelo comenzó a generar explícitamente:

`<think>`

antes de entregar la respuesta solicitada.

Se probaron:

`--reasoning off`

y posteriormente:

`--reasoning-budget 0`

El comportamiento no cambió.

En ambos casos el modelo consumió el límite de generación antes de producir
el marcador exacto requerido por el smoke test.

Resultado:

**FAIL**

## 10. Clasificación de incidentes de preflight

Durante F1.24H ocurrieron además dos incidentes que no deben atribuirse
al candidato:

1. uso inicial de un TMPDIR incorrecto, causando EROFS;
2. ausencia temporal de la entrada de `/etc/hosts`, causando 502.

Ambos fueron identificados y corregidos antes de evaluar la compatibilidad
real del modelo.

Por lo tanto no forman parte del resultado negativo de Qwen3.6.

## 13. Resultado final

**F1.24H: NOT SELECTED**

Qwen3.6-35B-A3B IQ4_XS demostró:

- compatibilidad con el nuevo runtime llama.cpp;
- carga CUDA correcta;
- offload completo;
- inferencia local correcta;
- conectividad SRT correcta.

Sin embargo, no resultó compatible con Claude Code en la configuración
reproducible utilizada por CumpleIA.

Las dos rutas evaluadas fallaron por motivos diferentes:

1. template nativo:
   incompatibilidad Jinja con la secuencia de mensajes de Claude Code;

2. chatml:
   generación persistente de `<think>` aun con reasoning desactivado.

El descarte se debe por tanto a **incompatibilidad de integración**,
no a incapacidad de inferencia del modelo ni a una falla del transporte SRT.

No se justifica continuar con contextos superiores ni ejecutar RAT funcional.

## 14. Decisión

Qwen3.6-35B-A3B IQ4_XS queda descartado como candidato local para la
arquitectura actual de CumpleIA.

El runtime histórico permanece intacto.

El checkout paralelo:

`~/runtime/llama.cpp-qwen36`

puede conservarse como evidencia técnica y para futuras reevaluaciones,
pero no sustituye al runtime local canónico actualmente validado.
