## Candidatos

La segunda ronda conserva los tres candidatos de la primera para obtener una
segunda observación comparable:

| Candidato | Clase | Modelo/transporte |
|---|---|---|
| `claude-sonnet-5` | cloud | Anthropic `claude-sonnet-5` |
| `deepseek-v4-pro` | cloud | DeepSeek `deepseek-v4-pro` |
| `qwen3-4b-local` | local | llama.cpp, endpoint local aislado existente |

Qwen3-4B continúa como baseline local de bajo coste, no como candidato local
principal recomendado. No se agrega todavía un modelo local mayor: la GPU
NVIDIA GeForce RTX 5060 Laptop dispone de 8 GiB y Qwen3-8B ya fue descartado
para esta configuración porque el prefill de Claude Code no completó dentro de
300 segundos. La selección de un reemplazo local requiere un preflight
separado; no se debe descargar ni incorporar uno durante una ronda comparable.

## Presupuesto y reglas de ejecución

- una única ejecución autoritativa por candidato;
- timeout de run y transporte: 1.800 segundos;
- mismo baseline, tarea, perfil, managed settings y aislamiento SRT;
- sin reintentos, cambios de prompt ni intervención humana durante cada run;
- las credenciales cloud se resuelven sólo desde sus variables de entorno y no
  se versionan;
- la ronda no se inicia mientras falte una credencial cloud declarada o falle
  el preflight local.

No se fija un tope monetario de aborto, igual que en F1.20C. Se conservarán
duración, estado trusted y, cuando el proveedor los entregue, tokens/coste
cloud. Para Qwen se conservarán tiempo y configuración del runtime.
