# F1.18D-B — Integración Claude Code con LLM local

**Fecha:** 2026-09-02  
**Estado:** PASS

## 1. Objetivo

Validar que Claude Code pueda utilizar un backend LLM ejecutado localmente mediante `llama-server`, manteniendo las restricciones de seguridad establecidas por Sandbox Runtime (SRT).

La validación debía demostrar:

- compatibilidad entre Claude Code y el endpoint Anthropic-compatible del runtime local;
- funcionamiento de Claude Code directamente contra el LLM local;
- funcionamiento de Claude Code dentro de SRT;
- acceso al backend únicamente mediante el hostname autorizado `llm-local.cumpleia`;
- mantenimiento del bloqueo al acceso directo a localhost desde el sandbox;
- ausencia de ampliaciones generales de red o permisos de escritura.

## 2. Dependencias de fases anteriores

Esta validación utiliza la arquitectura establecida y validada en:

- F1.18D-A — arquitectura de transporte local;
- F1.18D-A2 — validación con runtime LLM real.

El backend local utilizado es:

- runtime: `llama.cpp / llama-server`;
- commit llama.cpp: `b95502ba9aa0eb73a2f4fc8878d7fbe6a847a0b9`;
- modelo de validación: `Qwen3.5-0.8B-Q4_0.gguf`;
- GPU: NVIDIA RTX 5060 Laptop, 8 GB VRAM;
- CUDA Toolkit: 13.1;
- dirección dedicada de loopback: `127.77.18.1`;
- hostname controlado: `llm-local.cumpleia`;
- puerto: `18080`.

El modelo utilizado en esta prueba es exclusivamente un modelo de validación del transporte e integración. No constituye todavía la selección definitiva del modelo local para tareas de programación.

## 3. Arquitectura validada

El flujo sometido a prueba fue:

```text
Claude Code
    |
    v
Sandbox Runtime (SRT)
    |
    v
proxy / allowlist SRT
    |
    v
llm-local.cumpleia
    |
    v
127.77.18.1:18080
    |
    v
llama-server
    |
    v
Qwen3.5-0.8B local
La política SRT mantiene autorizado explícitamente el hostname:
llm-local.cumpleia
sin habilitar acceso general a localhost ni sockets Unix para el proceso sandboxeado.

## 4. Compatibilidad Anthropic de llama-server

Aunque la ayuda de `llama-server` no mostraba inicialmente una opción explícita denominada Anthropic, se verificó empíricamente que el servidor implementa el endpoint:

```text
POST /v1/messages
Una solicitud directa utilizando headers y estructura Anthropic obtuvo HTTP 200 y una respuesta con estructura compatible con Messages API.
Por tanto, no fue necesario introducir un proxy o adaptador adicional entre Claude Code y llama-server.
El endpoint base utilizado por Claude Code fue:
ANTHROPIC_BASE_URL=http://llm-local.cumpleia:18080
## 5. Primera prueba Claude Code y diagnóstico
La primera ejecución de Claude Code contra el backend local no produjo una respuesta final.
Se habilitó el diagnóstico mediante:
--debug-file /tmp/f118db-claude-debug.log
El log confirmó que Claude Code sí alcanzaba el backend y enviaba solicitudes al endpoint:
[API REQUEST] /v1/messages source=generate_session_title
[API REQUEST] /v1/messages source=sdk
La solicitud principal fallaba con HTTP 500 debido al chat template incluido en el modelo:
Error: Jinja Exception: System message must be at the beginning.
Esto permitió descartar como causa:
- resolución del hostname;
- conectividad hacia llama-server;
- incompatibilidad básica con /v1/messages;
- autenticación del transporte.
El problema correspondía al procesamiento de la secuencia de mensajes por el template Jinja del modelo.
## 6. Override del chat template
Para mantener la arquitectura sin introducir un proxy adicional, se reinició llama-server utilizando el template incorporado chatml:
./build/bin/llama-server \
  -m ~/runtime/local-llm/models/Qwen3.5-0.8B-Q4_0.gguf \
  --host 127.77.18.1 \
  --port 18080 \
  -ngl 99 \
  -c 4096 \
  --chat-template chatml
El servidor cargó correctamente el modelo y quedó escuchando exclusivamente en:
127.77.18.1:18080
Con este cambio desapareció el error:
System message must be at the beginning.
## 7. Ajuste de ventana de contexto
La siguiente ejecución avanzó correctamente hasta el backend, pero Claude Code generó una solicitud superior al contexto inicialmente configurado:
request (4822 tokens) exceeds the available context size (4096 tokens)
Esto confirmó nuevamente que el transporte y el chat template ya funcionaban.
Se amplió exclusivamente la ventana de contexto de llama-server:
-c 16384
El servidor confirmó:
n_ctx_slot = 16384
model loaded
listening on http://127.77.18.1:18080
La configuración utilizada para las pruebas finales fue por tanto:
./build/bin/llama-server \
  -m ~/runtime/local-llm/models/Qwen3.5-0.8B-Q4_0.gguf \
  --host 127.77.18.1 \
  --port 18080 \
  -ngl 99 \
  -c 16384 \
  --chat-template chatml
## 8. Claude Code contra LLM local fuera de SRT
Se ejecutó Claude Code utilizando el backend local mediante las variables de transporte Anthropic.
Para esta prueba se utilizó el identificador lógico de modelo `local` y se deshabilitó temporalmente el enforcement asociado a modelos desconocidos mediante:
CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1
Claude Code mostró el aviso no fatal:
[claude-code:unrecognized_model] {"model":"local","query_source":"generate_session_title"}
y posteriormente devolvió correctamente el marcador solicitado:
F1.18D-B-CLAUDE-LOCAL-OK
Resultado:
Claude Code -> llama-server -> Qwen3.5 local: PASS
## 9. Claude Code contra LLM local dentro de SRT
La misma integración se validó posteriormente dentro de Sandbox Runtime.
La primera ejecución falló con:
```text
EROFS: read-only file system, mkdir '/tmp/claude'
Este error no estaba relacionado con el transporte ni con el backend LLM. Claude Code intentaba utilizar /tmp, mientras que la política SRT mantiene ese filesystem sin permisos generales de escritura.
Se reutilizó el directorio de runtime previamente autorizado:
/home/cumplebench/runtime/tmp
mediante:
TMPDIR=/home/cumplebench/runtime/tmp
Sin realizar cambios adicionales en la política SRT ni habilitar escritura general sobre /tmp, Claude Code ejecutado dentro del sandbox devolvió correctamente:
F1.18D-B-SRT-LOCAL-OK
Resultado:
Claude Code -> SRT -> llm-local.cumpleia -> llama-server -> Qwen3.5 local: PASS
## 10. Validación negativa de acceso directo a localhost
Después de validar la inferencia mediante el hostname permitido, se verificó que el sandbox continuara sin poder acceder directamente a localhost.
La prueba desde SRT contra:
http://127.0.0.1:18080/
produjo:
curl: (7) Failed to connect to 127.0.0.1 port 18080 after 0 ms: Couldn't connect to server
HTTP=000
Resultado:
Acceso directo desde SRT a 127.0.0.1:18080: BLOCKED / PASS
Esto confirma que la integración con el LLM local no requirió habilitar localhost de forma general dentro del sandbox.
## 11. Configuración de transporte validada
La integración final utiliza:
ANTHROPIC_BASE_URL=http://llm-local.cumpleia:18080
ANTHROPIC_AUTH_TOKEN=<dummy-local-token>
ANTHROPIC_MODEL=local
ANTHROPIC_DEFAULT_SONNET_MODEL=local
ANTHROPIC_DEFAULT_HAIKU_MODEL=local
TMPDIR=/home/cumplebench/runtime/tmp
Para la prueba se utilizó además:
CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1
debido a que Claude Code 2.1.252 no reconoce el identificador lógico local como modelo conocido.
El token local es únicamente un valor ficticio utilizado para satisfacer la interfaz compatible con Anthropic. No constituye una credencial real del backend local.
## 12. Consideraciones y riesgos residuales
La validación confirma la compatibilidad técnica del transporte, pero quedan consideraciones para las rondas posteriores del benchmark:
- el modelo Qwen3.5-0.8B utilizado aquí es un modelo pequeño de validación y no representa todavía el candidato definitivo para generación de código;
- Claude Code continúa mostrando unrecognized_model para el identificador local;
- se utilizó CLAUDE_CODE_DISABLE_UNKNOWN_MODEL_WINDOW_ENFORCEMENT=1 como mecanismo temporal de integración;
- el template original del modelo no fue compatible con la secuencia de mensajes generada por Claude Code y fue necesario utilizar --chat-template chatml;
- la ventana de contexto de 4096 tokens fue insuficiente y se amplió a 16384 tokens;
- la política SRT autoriza el hostname llm-local.cumpleia, no un puerto específico;
- por esa razón se mantiene el aislamiento mediante la dirección loopback dedicada 127.77.18.1;
- continúa siendo requisito del benchmark verificar la ausencia de listeners wildcard antes de las ejecuciones relevantes;
- la selección de un modelo local definitivo deberá considerar calidad de código, tool use, contexto, velocidad, memoria y compatibilidad con Claude Code.
## 13. Resultado
F1.18D-B: PASS
Se demostró empíricamente que Claude Code puede utilizar un LLM local ejecutado mediante llama-server, tanto fuera como dentro de Sandbox Runtime, sin habilitar acceso general a localhost.
El flujo validado es:
Claude Code
  -> SRT
  -> proxy / allowlist SRT
  -> llm-local.cumpleia
  -> 127.77.18.1:18080
  -> llama-server
  -> LLM local
Las restricciones principales de seguridad permanecieron activas y la prueba negativa confirmó que 127.0.0.1:18080 sigue siendo inaccesible directamente desde el sandbox.
