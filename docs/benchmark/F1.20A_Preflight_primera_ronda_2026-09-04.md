## 1. Objetivo

Comprobar que el harness cerrado en F1.19A–E está listo para una comparación
real y evitar una ronda cuyo resultado no mida el trabajo solicitado.

## 4. Gate funcional

`rat-default` demuestra que el baseline migra correctamente y que el fixture,
la configuración, los privilegios y RLS conservan sus invariantes. No demuestra
que el candidato haya implementado una tarea nueva.

Por diseño, un candidato que no modifica nada puede superar `rat-default` sobre
el baseline actual. Por ello no se ejecutará una comparación pagada ni se
declarará un ganador usando solo ese perfil: sería evidencia técnicamente válida
pero funcionalmente irrelevante.

## 5. Datos necesarios para abrir la ronda

La ronda debe fijar antes de ejecutarse:

1. una tarea común con criterios de aceptación observables;
2. un verifier trusted específico que falle ante una solución vacía;
3. los candidatos definitivos y sus identificadores exactos de modelo;
4. un único baseline Git para todos;
5. el mismo timeout y presupuesto por candidato;
6. una matriz de comparación que separe corrección, seguridad, cambios y coste.

El baseline recomendado es el commit que incorpore este preflight. Para una
primera tarea de código acotada, la opción recomendada del roadmap es la mejora
de Módulo 1 «mostrar N/A por sección», porque permite criterios funcionales y
pruebas trusted deterministas sin abrir todavía un módulo nuevo.
