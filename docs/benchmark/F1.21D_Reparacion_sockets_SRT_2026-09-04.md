# F1.21D — Reparación de sockets puente SRT

**Fecha:** 2026-09-04
**Estado:** corrección implementada; sonda final pendiente en el repositorio canónico

## Incidencia

Las corridas de segunda ronda de Qwen3-4B y Claude cerraron sin llegar a
ejecutar una tarea: ambos agentes informaron `Failed to create bridge sockets
after 5 attempts`. Sus verificadores de infraestructura y manifests quedaron
íntegros, pero el contrato funcional no pudo ser evaluado porque el agente no
arrancó.

## Causa

El harness ubicaba `TMPDIR` dentro de una ruta que incorporaba el `runId`
completo. Claude Code crea sockets bajo `TMPDIR/cc-socks`; las rutas de segunda
ronda medían entre 92 y 96 caracteres antes del nombre del socket, demasiado
cerca del límite Unix de 108 bytes. Una ronda anterior funcional tenía una base
de 82 caracteres.

Una sonda SRT aislada confirmó que SRT y Claude Code arrancan correctamente
con la misma política cuando no se alcanza ese límite.

## Corrección

- Se agregó `/home/cumplebench/benchmark-tmp/<hash16>` como `TMPDIR` corto y
  determinista por `runId`.
- El directorio permanece bajo una raíz trusted y se crea con modo `0700`.
- La política SRT permite escribir sólo en ese subdirectorio, además del
  workspace y el directorio de configuración Claude por corrida.
- La limpieza trusted elimina también el TMPDIR corto asociado, verificando
  raíz, nombre y ausencia de symlinks antes de borrar.
- Se añadió una regresión que asegura margen para `cc-socks` y un nombre de
  socket representativo bajo el límite Unix.

## Validación

La suite trusted tras el cambio terminó con `18 passed, 2 skipped`; Ruff y
Black pasaron. Falta ejecutar una sonda SRT `--print` con el TMPDIR corto y sin
un endpoint de modelo válido antes de habilitar nuevos `runId` de candidatos.

Las evidencias ya cerradas no se modifican ni se reutilizan.
