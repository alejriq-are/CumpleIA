# F1.21D — Reparación de sockets puente SRT

**Fecha:** 2026-09-04
**Estado:** PASS

## Incidencia

Las corridas de segunda ronda de Qwen3-4B y Claude cerraron sin llegar a
ejecutar una tarea: ambos agentes informaron `Failed to create bridge sockets
after 5 attempts`. Sus verificadores de infraestructura y manifests quedaron
íntegros, pero el contrato funcional no pudo ser evaluado porque el agente no
arrancó.

## Causa

El harness ubicaba `TMPDIR` dentro de una ruta que incorporaba el `runId`
completo. Claude Code crea sockets bajo `TMPDIR/cc-socks`; las rutas de segunda
ronda medían entre 92 y 96 caracteres antes del nombre del socket, demasiado
cerca del límite Unix de 108 bytes. Una ronda anterior funcional tenía una base
de 82 caracteres.

Una sonda SRT aislada confirmó que SRT y Claude Code arrancan correctamente
con la misma política cuando no se alcanza ese límite.

## Corrección

- Se agregó `/home/cumplebench/benchmark-tmp/<hash16>` como `TMPDIR` corto y
  determinista por `runId`.
- El directorio permanece bajo una raíz trusted y se crea con modo `0700`.
- La política SRT permite escribir sólo en ese subdirectorio, además del
  workspace y el directorio de configuración Claude por corrida.
- La limpieza trusted elimina también el TMPDIR corto asociado, verificando
  raíz, nombre y ausencia de symlinks antes de borrar.
- Se añadió una regresión que asegura margen para `cc-socks` y un nombre de
  socket representativo bajo el límite Unix.

## Validación

La suite trusted en el repositorio canónico terminó con `22 passed, 2 skipped`;
Ruff y Black pasaron. Una sonda SRT aislada con el TMPDIR corto, el transporte
local y el prompt mínimo `Reply exactly OK` respondió `OK` y creó el socket mux
en `/home/cumplebench/benchmark-tmp/<hash16>`, sin error de bridge sockets.

La sonda no fue una corrida RAT, no usó tarea ni credenciales cloud, y sus
directorios temporales fueron eliminados después de validar.

Las evidencias ya cerradas no se modifican ni se reutilizan.

## Runs posteriores a la reparación

Los `runId` de Qwen y Claude que alcanzaron el fallo de sockets permanecen
cerrados como evidencia de incidencia y no se reutilizan. Las corridas
autoritativas posteriores a la reparación son:

- `run-qwen3-4b-local-r2.json`;
- `run-claude-sonnet-5-r4.json`.

DeepSeek mantiene su `run-deepseek-v4-pro.json` original, ya que no se inició
antes de detectar el fallo común.

## Corrección posterior de creación de TMPDIR

La primera ejecución posterior, `qwen3-4b-local-r2`, expuso que la raíz común
`/home/cumplebench/benchmark-tmp` se creaba sin `exist_ok=True`. El defecto
ocurre antes de iniciar el agente y no modifica evidencia cerrada. El harness
ahora tolera la existencia de esa raíz y cuenta con una prueba de regresión.

El workspace parcial de `r2` se preserva sin cambios. La ejecución efectiva de
Qwen posterior a esta corrección usará `run-qwen3-4b-local-r3.json`.
