# F1.28 — Cierre de selección de modelos locales

Fecha: 2026-09-11

## 1. Objetivo

Cerrar formalmente la fase de evaluación comparativa de modelos locales para CumpleIA y seleccionar el candidato principal para uso operativo con Claude Code.

## 2. Decisión final

Se selecciona **Qwen3.6-35B-A3B IQ4_XS** como modelo local principal para CumpleIA.

La selección se basa en que fue el único candidato que combinó de forma suficiente:

- rendimiento operativo aceptable;
- compatibilidad efectiva con Claude Code;
- tool use funcional;
- capacidad agentic real;
- finalización de una RAT completa dentro de un tiempo razonable.

## 3. Comparación de candidatos

| Modelo | Rendimiento | Claude Code | Tool use | RAT / Agentic | Decisión |
|---|---|---|---|---|---|
| Qwen3.6-35B-A3B IQ4_XS | Bueno | PASS | PASS | RAT completada | **SELECCIONADO** |
| Qwen3-Coder-30B-A3B Q4_K_M | Bajo en contexto real | PASS | PASS | TIMEOUT / incompleto | No |
| DeepSeek-Coder-V2-Lite-Instruct Q4_K_M | Excelente | PASS básico | FAIL stack actual | Mini-agentic FAIL | No |
| Ministral-3-14B-Instruct-2512 Q4_K_M | Bueno sintético / bajo real | FAIL template | No evaluable | No procede | No |

## 4. Qwen3.6-35B-A3B IQ4_XS

Qwen3.6 queda como baseline operativo local.

Resultados relevantes:

- configuración MoE óptima: `-ncmoe 32`;
- buen rendimiento sintético y real;
- compatibilidad con Claude Code validada;
- tool use funcional;
- RAT completada aproximadamente en 10m30s;
- defectos detectados en la RAT fueron de integración y no de incapacidad agentic general.

## 5. Qwen3-Coder-30B-A3B Q4_K_M

La recalibración con `-ncmoe 32` mejoró significativamente su rendimiento sintético.

Sin embargo:

- la mini-prueba agentic fue PASS fuerte;
- la RAT completa alcanzó TIMEOUT;
- duración: 1814.351633 s;
- implementación quedó incompleta;
- se verificaron dos errores TypeScript;
- no se completaron tests frontend;
- viabilidad operativa: FAIL.

Conclusión: no seleccionado.

## 6. DeepSeek-Coder-V2-Lite-Instruct Q4_K_M

Configuración óptima:

- `-ngl 20`.

Resultados relevantes:

- pp512 ~1439.40 t/s;
- tg128 ~74.27 t/s;
- pp16384 936.06 t/s;
- tg256 56.87 t/s;
- `/v1/messages` ~58.69 t/s;
- SRT ~58.36 t/s;
- Claude Code básico ~57.78 t/s.

El rendimiento fue el mejor entre los candidatos evaluados.

Sin embargo, el flujo agentic falló:

- mini-agentic FAIL;
- el modelo generó tool calls como texto;
- Claude Code no ejecutó las herramientas;
- llama.cpp reportó:
  - `tool_mode: NONE`;
  - `supports_tools: false`;
  - `chat_format: peg-native`;
  - `reasoning_format: deepseek`.

Conclusión: performance PASS / agentic tool compatibility FAIL con el stack actual.

No se ejecutó RAT completa.

## 7. Ministral-3-14B-Instruct-2512 Q4_K_M

Evaluación ejecutiva:

- tamaño: 7.67 GiB;
- parámetros: 13.51B;
- pp512: 1298.91 t/s;
- tg128: 39.39 t/s;
- `/v1/messages`: PASS;
- rendimiento real de generación en servidor: ~15.39 t/s.

Claude Code falló por incompatibilidad del template Jinja:

`Only user, assistant and tool roles are supported, got system`

No se continuó con tool use ni mini-agentic.

Conclusión: no seleccionado.

## 8. Política operativa resultante

### Modelo local principal

**Qwen3.6-35B-A3B IQ4_XS**

Uso recomendado:

- desarrollo cotidiano;
- cambios acotados;
- lectura y edición de código;
- pruebas locales;
- tareas agentic de complejidad media.

### Modelos cloud

Mantener Claude / DeepSeek cloud para:

- arquitectura;
- cambios críticos;
- refactors complejos;
- revisión final;
- problemas de alta dificultad;
- validación cruzada del modelo local.

## 9. Candidatos para reevaluación futura

### DeepSeek-Coder-V2-Lite

Reevaluar si una futura versión de llama.cpp o un template/parser adaptado soporta correctamente su protocolo nativo de tool-calling.

### Ministral 3 14B

Reevaluar si una futura versión del template permite mensajes `system` compatibles con Claude Code y mejora el rendimiento real del servidor.

## 10. Cierre

Se considera cerrada la fase de selección comparativa de modelos locales.

**Modelo seleccionado: Qwen3.6-35B-A3B IQ4_XS.**

La próxima fase será la operacionalización y hardening del runtime local seleccionado.
