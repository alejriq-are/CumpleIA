### Falso negativo nominal y defectos reales

El verifier contiene la regex conocida que exige `organizaciones[0]`, mientras
el helper usa `memberships[0]`. Ese rechazo por nombre es un falso negativo
nominal, pero **no explica ni invalida los defectos funcionales adicionales**:

- El helper devuelve `null` cuando falta `organizationParam`, aun con
  membresías disponibles. Debía devolver de forma segura la primera membresía;
  `null` corresponde a una lista vacía. El fallback para ID inválido no cubre
  el caso de parámetro ausente.
- `AutodiagnosticoPage` pasa `activeOrganization` a
  `AutodiagnosticoWorkspace`, cuya firma no declara esa prop.
  El workspace además sigue inicializando `orgId` con `organizaciones[0].id`,
  sin integrar la organización seleccionada.
- En `organizacion/page.tsx`, el JSX usa `OrganizacionForm` sin importarlo.
- El selector reutilizable y la integración quedaron incompletos.
- No se completaron los tests frontend requeridos.

### Type-check posterior: dos errores confirmados

El primer intento no pudo ejecutar TypeScript (`tsc: not found`) por ausencia
de dependencias en el workspace clonado. Tras instalar con `npm ci`,
`npm run type-check` reportó **FAIL con dos errores**:

| Error | Interpretación |
|---|---|
| `Property 'activeOrganization' does not exist` | Prop no declarada en `AutodiagnosticoWorkspace` |
| `Cannot find name 'OrganizacionForm'` | Componente usado sin importar |

La validación corresponde al frontend del workspace de F1.26 bajo
`/home/cumplebench/benchmark-workspaces/f1.26-rat-active-org-qwen3-coder-30b-a3b-local`.
No es un type-check del producto actual ni una nueva RAT. Los warnings de
Node 20 frente a paquetes Supabase que requieren Node 22 y los avisos de
`npm audit` son condiciones del entorno/dependencias; no se atribuyen al
modelo ni explican esos dos errores de integración.
