# F1.21B — Verifier trusted: organización actual segura

**Fecha:** 2026-09-04
**Estado:** PASS

## Alcance

Se implementó el perfil `rat-organization-current-v1` para la segunda tarea
funcional del benchmark. El perfil encadena `rat-default` y un contrato aislado
para `GET /organizations/current`.

## Frontera de confianza

El código candidato se monta en sólo lectura dentro de un contenedor que usa:

- red `none`;
- filesystem raíz de sólo lectura y `/tmp` efímero `noexec,nosuid`;
- capacidades eliminadas, `no-new-privileges`, máximo 128 procesos y 256 MiB;
- ninguna credencial ni URL de base de datos real.

El contrato usa dobles de sesión y perfil para ejercitar FastAPI sin otorgar al
código candidato acceso a los secretos del PostgreSQL trusted. `rat-default`
continúa comprobando de forma separada migraciones, fixture, privilegios y RLS
de los tenants A/B.

## Controles funcionales

El verifier comprueba:

- existencia única de `GET /organizations/current` y modelo de respuesta
  `OrganizationDetailOut`;
- selección con `X-Organization-Id` y dependencia
  `require_permission(Permission.view_content)`;
- respuesta con sólo `id`, `name`, `rut`, `industry` y `size` de la fila
  solicitada;
- lectura HTTP exitosa para un `viewer` miembro;
- respuesta HTTP `403` cuando la membresía no existe;
- respuesta `404` para una fila ausente tras autorización simulada;
- presencia de pruebas backend del candidato y prohibición de modificar el
  harness, migraciones o seed.
